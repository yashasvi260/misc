SQL Server → Lakeflow → Medallion Pipeline

A query-based Lakeflow Connect ingestion, a Delta control table, and a Spark Declarative Pipeline turn SQL Server tables into bronze, silver, and gold — and adding or disabling a source table is a row change, not a code change.

Architecture

One control table drives three consumers, and one daily job triggers both pipelines in order: reconcile the table list, run ingestion, then run the transform.

Components

What each piece is responsible for, grouped by where it sits in the flow above.

Bundle & control table

Bundle root

Catalog/schema variables, the control table path, the SQL warehouse ID, and the dev/prod targets.

Control table DDL

Creates sqlserver_ingestion_control and seeds the two example rows: source/destination mapping, driving column, primary keys, SCD type, enabled flag.

Shared read helper

fetch_enabled_tables() — queries the control table via a SQL warehouse. Used by both the generator and the reconciler.

Ingestion

Ingestion pipeline resource

Generated Lakeflow Connect pipeline definition — never hand-edited, overwritten by the generator or the reconciler. No schedule of its own — triggered daily by run_ingestion.

Bootstrap generator

Control table → generated pipeline YAML. Runs via a GitHub Actions workflow, on demand: to bootstrap the pipeline, or any time you want to review a change as a pull request before it's deployed.

Daily orchestration

Scheduled job

Once-daily Databricks Job: reconcile → run_ingestion → run_transform, chained with depends_on so a reconcile failure blocks that day's run. Ships paused, with --apply left off, until the dry-run output is verified by hand.

Live pipeline reconciler

Control table → deployed pipeline, via GET → replace objects → PUT the full spec. Dry-run by default; --apply is opt-in.

Transform pipeline

Declarative pipeline resource

Serverless Spark Declarative Pipeline. Passes bronze_catalog, bronze_schema, and control_table in as configuration. No schedule of its own — triggered daily by run_transform.

Raw layer

Loops over enabled control-table rows; one streaming raw_<table> view per row.

Silver layer

One create_auto_cdc_flow per enabled row, keyed by primary_keys, sequenced by driving_column, historized per scd_type.

Gold layer

gold_customer_order_summary and gold_daily_order_volume — aggregates over silver, raw SQL Server column casing.

Workflow: adding or disabling a table

Same legend as above. Changing a row in the control table reaches production one of two ways — automatically, on the next daily run, or manually, if you're bootstrapping or reviewing a change first.

Before deploying

Flagged as unverified

  • table_configuration.driving_column — best-guess field name for query-based ingestion's watermark column. Confirm with databricks bundle schema or the Lakeflow Connect SQL Server docs before deploying.
  • No gateway pipeline — CDC-based SQL Server ingestion requires a separate gateway pipeline; this assumes query-based mode doesn't. If it does, add a gateway_definition resource and reference it from ingestion_gateway_id instead of connection_name.
  • Pipelines API spec nesting — the reconciler assumes GET /api/2.0/pipelines/{id} nests the editable fields under a top-level spec key. Run reconcile_ingestion_pipeline.py once without --apply and read the printed response before ever enabling the schedule.
